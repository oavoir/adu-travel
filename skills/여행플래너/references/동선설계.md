# 동선 설계 — 이동시간 산출과 하루 코스 조립

일정을 "몇 시에 어디서 어디로"까지 확정하려면 구간 이동시간이 필요하다. 유료 라우팅 API 없이 실제로 동작하는 경로가 있고, 조용히 틀린 값을 뱉는 함정도 있다. 이 문서는 실측으로 확인한 것만 담는다.

## 1. 이동시간 — 폴백 사다리

**호출이 필요 없는 것부터 쓴다.** 무료 공용 API는 개인이 가볍게 쓰라고 열어둔 자원이지 자동화 도구가 기본값으로 두들기라고 있는 게 아니다(정책 상세는 7절).

| 순위 | 수단              | 방법                                           | 외부 호출                  |
| :--- | :---------------- | :--------------------------------------------- | :------------------------- |
| ①    | **브라우저**      | Google Maps 경로 페이지를 브라우저 도구로 읽기 | **없음** (사용자 브라우저) |
| ②    | **일본 대중교통** | Yahoo! 乗換案内 (요금·환승까지)                | 일반 웹 조회               |
| ③    | **추정식**        | 직선거리 회귀식 (아래 4절)                     | **없음**                   |
| ④    | 자동차 정밀       | OSRM 데모 서버                                 | 공용 API                   |
| ⑤    | 대중교통 정밀     | Transitous `/api/v1/plan`                      | 공용 API · **옵트인**      |

**①이 기본이다.** 실측에서 브라우저로 Google Maps 경로를 열면 소요시간·요금·노선명·배차간격·대안 경로까지 전부 읽혔다. 사용자 자신의 브라우저로 사용자가 볼 수 있는 페이지를 보는 것이라 남의 인프라를 쓰지 않는다.

**③으로 대부분 해결된다.** 일정 조립 단계에서는 분 단위 정확도가 필요 없다. "이 두 곳이 한 나절에 들어가는가"만 알면 되고, 회귀식의 잔차 표준편차 6.4분이면 그 판단에 충분하다. **정밀한 값은 최종 검산에서 핵심 구간 몇 개만** 확인하면 된다.

**④⑤는 예외 경로다.** 아래 조건을 전부 만족할 때만 쓴다.

- 하루 일정당 **10건 이내**로 억제하고 결과를 반드시 캐싱한다
- User-Agent에 **도구 이름과 연락 수단**을 넣는다 (정책 요구사항)
- ⑤ Transitous는 **사용자가 명시적으로 요청할 때만** 쓴다. 기본 경로가 아니다

### 호출 형식 (실측 확인)

```
# 지오코딩 — 장소명을 좌표로
https://nominatim.openstreetmap.org/search?q=Sensoji+Temple+Tokyo&format=json

# 대중교통
https://api.transitous.org/api/v1/plan?fromPlace=35.6812,139.7671&toPlace=35.7148,139.7966&transitModes=TRANSIT

# 도보
https://api.transitous.org/api/v1/plan?fromPlace=<lat,lon>&toPlace=<lat,lon>&directModes=WALK

# 자동차 (경도,위도 순서임에 주의)
https://router.project-osrm.org/route/v1/driving/139.7671,35.6812;139.7966,35.7148?overview=false

# 일본 대중교통
https://transit.yahoo.co.jp/search/result?from=東京駅&to=浅草駅
```

### ⚠️ 함정 1 — OSRM 데모는 도보 프로필을 무시한다

`profile`을 `foot`으로 바꿔도 driving과 바이트 단위로 똑같은 값이 돌아온다. 실측에서 5,744m를 550초로 계산했는데 이건 시속 37.6km, 명백한 자동차 속도다. 데모 서버는 car 프로필만 호스팅하면서 URL의 프로필을 조용히 무시한다. **OSRM으로 도보 시간을 뽑으면 실제의 약 1/9이 나오고, 그 값으로 짠 일정은 현장에서 통째로 무너진다.** 도보는 반드시 Transitous `directModes=WALK`를 쓴다.

### ⚠️ 함정 2 — Transitous는 커버리지 구멍에서 오답을 낸다

에러를 내는 게 아니라 그럴듯한 숫자를 낸다. 실측에서 오사카역→난바(직선 4.2km)에 **358분**을 반환했고, 대안 경로 5개까지 붙여서 정상 응답처럼 보였다. 간사이 지역 피드가 없어 장거리 철도로 우회 경로를 짜낸 결과다.

정상 확인된 곳: 도쿄·파리·서울·뉴욕·로마·런던·방콕·바르셀로나·아테네·프라하·홍콩·시드니
결과 0건 또는 오답: 오사카·교토·두바이·발리·멕시코시티

그래서 타당성 필터가 선택이 아니라 필수다.

### 타당성 필터 (모든 API 결과에 무조건 적용)

```
model(분) = 20.6 + 1.65 × 직선거리_km
하한 = max(3, 0.35 × model)
상한 = 2.5 × model + 15

결과가 이 범위 밖이면 폐기하고 추정식으로 대체한다.
```

실측 18개 구간에서 정상값 오탐 0건, 오사카 358분 케이스는 정상 차단됐다.

### 최후수단 추정식

6개 도시 18개 구간을 실측해 회귀한 식이다. 단순 배수(km/h)는 틀린 모델이다 — 짧은 구간은 시속 7.4km, 긴 구간은 15.0km로 2배 차이가 나는데, 원인은 역까지 걸어가고 기다리고 환승하고 내려서 또 걷는 **고정 오버헤드**이고 이건 거리와 무관하기 때문이다.

```
대중교통_분 = 20.6 + 1.65 × 직선거리_km      (잔차 표준편차 6.4분)
도보_분     = 19.4 × 직선거리_km              (페이스 4.2km/h, 우회계수 1.36)
```

도시별 대중교통 유효속도 실측치 (참고용): 도쿄 14.4 / 서울 13.1 / 뉴욕 9.9 / 파리 8.3 / 런던 6.8 / 로마 4.9 km/h. 로마가 유난히 느린 건 우회계수가 2.12로 크기 때문이다.

### 🔴 공용 API 사용 정책 — 배포된 도구라서 더 엄격하다

세 서비스 모두 자원봉사로 운영되는 무료 공용 인프라다. 개인이 가끔 쓰는 것과 **배포된 도구가 여러 사용자에게서 기본값으로 호출하는 것은 정책상 전혀 다르다.** 정책 원문을 그대로 옮긴다.

**Transitous** — 가장 제약이 크다. 그래서 기본 경로에서 뺐다.

> "Transitous is not intended for commercial or for-profit purposes."
> "Please contact us before using any potentially resource-intensive API endpoints, **doing many requests (also from different users)**."

괄호 안의 "also from different users"가 배포된 플러그인을 정확히 가리킨다. **사용자가 명시적으로 요청할 때만 쓰고, 기본 동작으로 두지 않는다.** 오픈소스 도구는 소스 공개·연락·User-Agent·출처 표기를 갖추면 허용된다.

**Nominatim**

> "No heavy uses (an absolute maximum of 1 request per second)."
> "Results **must be cached** on your side."
> 앱은 "**switching should be possible without requiring a software update**" — 요청 시 서비스를 바꿀 수 있어야 한다.

마지막 조항 때문에 **엔드포인트를 하드코딩된 유일 경로로 취급하지 않는다.** Nominatim이 막히거나 정책이 바뀌면 브라우저 Google Maps 장소 검색으로 좌표·주소를 확보하는 경로로 갈아탄다. 지오코딩은 여행 1건당 10~20건 수준이라 bulk가 아니지만, User-Agent에 도구명과 연락 수단을 반드시 넣는다.

**OSRM 데모** — 셋 중 가장 관대하다.

> "Excessive use is not allowed. If your requests are impacting the service stability, we will block you."
> "Access to the demo server shall not be behind a paywall... it needs to be publicly accessible and featuring proper attribution."
> "Selling access to our demo server is strictly forbidden!"

제3자 앱의 사용을 허용하되 User-Agent와 출처 표기를 요구한다. **유료 상품 뒤에 두거나 접근을 파는 것은 금지**다.

### 실행 규칙

1. **기본은 호출 0회다.** 브라우저(①)와 추정식(③)으로 일정을 조립하고, 공용 API는 최종 검산의 핵심 구간에만 쓴다
2. **하루 일정당 10건 이내**로 억제하고 결과를 스크래치 파일에 캐싱한다. 같은 구간을 두 번 조회하지 않는다
3. **User-Agent에 도구 이름과 연락 수단**을 넣는다. 라이브러리 기본 UA는 정책 위반이다
4. **Transitous는 옵트인.** 사용자가 명시적으로 원할 때만
5. **유료 상품 뒤에 두지 않는다.** 이 스킬을 유료 서비스의 일부로 판매하면 OSRM 정책 위반이다
6. **출처를 표기한다** — 지도 데이터는 OpenStreetMap 기여자, 경로는 해당 서비스

⚠️ **이 스킬이 널리 배포되어 호출이 늘어나면 정책 위반 규모가 될 수 있다.** 규모가 커지는 조짐이 보이면 각 서비스에 사전 연락하거나, 사용자가 자기 API 키를 넣는 방식으로 전환해야 한다.

## 2. 지도 링크 — 검증된 템플릿

```
# 장소 검색
https://www.google.com/maps/search/?api=1&query={이름, 주소}

# 경로 (2점)
https://www.google.com/maps/dir/?api=1&origin={A}&destination={B}&travelmode={driving|walking|bicycling|two-wheeler|transit}

# 하루 코스를 링크 하나로 (driving/walking 전용)
https://www.google.com/maps/dir/?api=1&origin={A}&destination={Z}&waypoints={B}%7C{C}%7C{D}&travelmode=driving

# 국내 — 카카오맵
https://map.kakao.com/link/to/{이름},{lat},{lng}
https://map.kakao.com/link/from/{이름},{lat},{lng}/to/{이름},{lat},{lng}
https://map.kakao.com/link/by/{car|traffic|walk|bicycle}/...

# 애플 지도
https://maps.apple.com/?q={검색어}
https://maps.apple.com/?saddr={출발}&daddr={도착}&dirflg={d|w|r}
```

실측으로 드러난 제약 넷:

1. **`travelmode=transit`에 waypoints를 붙이면 실패한다.** "대중교통 경로를 계산할 수 없습니다"가 뜬다. 같은 구간이 waypoints 없이는 정상 동작하므로 원인은 waypoints다. → 하루 코스 1링크는 자동차·도보 전용이고, 대중교통은 구간별 링크로 쪼갠다.
2. **모호한 지명 하나가 경로 전체를 죽인다.** `waypoints=Imperial+Palace`를 넣자 도쿄 6km 경로가 "서비스 범위를 벗어난 검색"으로 실패했고, `Akihabara Station`으로 바꾸니 즉시 정상 동작했다. → 반드시 `이름, 도시, 국가` 형식이나 place_id를 쓴다. 단독 지명 금지.
3. **좌표를 넣으면 기하는 맞지만 라벨이 깨진다.** 도쿄역 좌표가 화면에 엉뚱한 상호로 표시된다. 사람이 볼 링크에는 이름 문자열을 쓴다.
4. **waypoint 상한은 모바일 브라우저 3개, 그 외 9개.**

**핀 목록 공유는 불가능하다.** Google Maps URLs API의 액션은 search·directions·map·street view 넷뿐이고 여러 핀을 묶어 공유하는 액션이 없다. My Maps와 저장 목록은 로그인이 전제라 URL만으로 못 만든다. 대안은 위의 multi-waypoint 링크 하나거나, KML/GeoJSON 파일을 만들어 사용자가 직접 임포트하는 것이다.

네이버 지도는 `nmap://` 앱 스킴이고 `appname` 파라미터가 없으면 동작하지 않는다. 모바일 전용이라 PC 공유용으로는 부적합하다.

## 3. Google Maps를 읽는 법

**WebFetch로는 절대 안 읽힌다.** 장소 페이지든 경로 페이지든 "Google 지도" 문자열만 돌아오는 JS 셸이다.

**브라우저 도구로는 완전히 읽힌다.** `navigate` 후 `get_page_text`를 쓰면 경로 소요시간·요금·노선명·배차간격·대안 경로까지 전부 나온다. 장소 페이지에서는 영업시간과 **"인기 시간대"(Popular Times) 혼잡 곡선**까지 읽히는데, 이건 "인기 스팟은 아침에" 규칙을 명소별 실데이터로 뒷받침할 수 있다는 뜻이다.

단 `read_page`는 빈 트리를 반환한다. 클릭 상호작용은 기대하지 말고 `get_page_text` 읽기 전용으로 설계한다.

## 4. 하루 코스 조립

### 하루 몇 곳인가

**기본 3곳, 상한 4곳.** 사전예약이 필요한 항목은 하루 1개까지.

근거는 취향이 아니라 물리적 상한이다. 박물관 관람객의 집중은 약 30분 후부터 하강하고(Falk 외 1985), 일부 연구는 20분 미만으로 본다(Serrell). Rick Steves 본인도 한 번에 2~~3시간이 한계라고 말한다. 실제 일정표를 세어보면 Rick Steves 파리 공식 일정이 하루 2~~4곳(중앙값 3), 하나투어 서유럽 9일 패키지가 관광일 평균 3.3곳이다.

### 클러스터링

핀을 전부 찍고 뭉친 덩어리를 찾아 그 구역에 반나절을 배정한다. 도보권(1.5km 이내)을 우선 묶는다.

**도심에서 멀리 떨어진 필수 명소는 전용일로 승격한다.** Rick Steves 파리 일정에서 베르사유는 하루를 통째로 쓰고 그날 시내 명소를 넣지 않는다. 이게 검증된 패턴이다.

### 제약이 클러스터링보다 우선한다

순서대로 적용한다.

**a. 휴관일 — 월요일로 하드코딩하면 안 된다.** 공식 사이트 실측만으로 이렇게 갈린다.

| 시설                           | 휴관                                                |
| :----------------------------- | :-------------------------------------------------- |
| 루브르 · 레이나소피아 · 경복궁 | 화요일                                              |
| 바티칸 박물관                  | 일요일 (매월 마지막 일요일만 오전 무료 = 초혼잡)    |
| 우피치 · 최후의 만찬           | 월요일                                              |
| 도쿄국립박물관                 | 월요일. 단 월요일이 공휴일이면 개관하고 다음날 휴관 |

목록에 없는 시설은 공식 사이트를 WebFetch로 직접 확인한다.

**b. 슬롯형 예약은 티켓이 일정을 결정한다.** 안네 프랑크 하우스는 현장 판매가 없고 매주 화요일 10:00 CEST에 정확히 6주 뒤 날짜분만 열리며 교환·환불·양도가 전부 불가다. 최후의 만찬은 15분 슬롯이라 일정에 15분으로 박아야 하고, 알람브라 나스르 궁전은 30분 슬롯을 놓치면 그날 입장이 안 된다. **이런 항목은 일정을 짜기 전에 예약 가능일부터 확인한다.**

**c. 유효 폐관은 표기 폐관에서 60분을 뺀 시각이다.** 대부분의 명소가 폐관 30~60분 전부터 티켓 판매를 멈추고 구역을 닫기 시작한다.

**d. 식사 앵커 — 주방이 닫히는 구간에 식사를 넣지 않는다.**

| 국가     | 점심        | 저녁        | 주방 닫힘                |
| :------- | :---------- | :---------- | :----------------------- |
| 스페인   | 14:00–15:30 | 21:00–23:00 | **16:00–20:30**          |
| 이탈리아 | 12:00–14:30 | 19:00–22:30 | **14:30–19:00**          |
| 프랑스   | 12:00–14:30 | 19:00~      | **14:30–18:00**          |
| 영국     | 12:00–14:30 | 18:00–20:30 | **14:30–18:00**          |

프랑스에서 14:30~18:00에 제대로 된 식사를 찾는 건 헛수고에 가깝고, 예외 간판이 `service continu`다. 영국 펍은 57%가 점심·저녁만 제공하고 종일 제공은 24%다. 미국 영업시간 패턴은 신뢰할 출처를 못 찾았으니 개별 확인한다.

**e. 유럽 일요일·월요일 조합이 이틀 연속 일정을 깬다.** 일요일은 쇼핑이 막히고 월요일은 박물관이 닫힌다. 독일 Ladenschlussgesetz는 일요일·공휴일 상점 전면 폐점을 명문화하고 기차역·공항·주유소·약국만 예외로 둔다. 폴란드는 2026년 상거래 가능 일요일이 8일뿐이다.

단 **레스토랑과 박물관은 이 규제 대상이 아니다.** "스위스는 일요일에 다 닫는다"는 틀린 말로, 400㎡ 초과 소매점만 금지되고 요식업은 정상 영업한다.

**f. 이탈리아행이면 파업 일정을 조회한다.** 교통인프라부가 [scioperi.mit.gov.it](https://scioperi.mit.gov.it/mit2/public/scioperi)에 예정 파업을 시간대까지 사전 게시한다. 최소보장 운행시간대는 06:00~~09:00과 18:00~~21:00이다. 프랑스는 최소 5영업일 전 예고 의무가 법으로 있다.

### 하루 안에서의 순서

- **개장 직후에 그날 최인기 1곳.** Rick Steves 파리 일정은 루브르 개장 30분 전, 오르세 15분 전, 베르사유 09:00 개장 전 도착을 분 단위로 지시한다. 베르사유는 일·화요일이 초혼잡이라 피한다.
- 브라우저로 Google Maps 장소 페이지의 "인기 시간대"를 읽어 혼잡 시간대를 실제로 확인한다.
- **도착일은 야외·도보 위주로 짜고, 앉는 활동과 고가치 명소를 넣지 않는다.** 흔한 조언과 달리 Rick Steves는 첫날을 가볍게 쉬라고 하지 않는다 — 오히려 "시차는 신선한 공기·햇빛·운동을 싫어한다"며 낮잠을 금한다. 포럼 합의도 활동의 양이 아니라 종류 문제로 본다. HOHO 버스·보트·연극처럼 앉는 활동이 시차 적응을 망치고, 첫 풀데이에 최고 명소를 배치하면 컨디션 때문에 낭비된다.
- 시차 적응 속도는 서향 하루 1.5시간, 동향 하루 1시간이다 (CDC Yellow Book 2026). 흔히 인용되는 "시간대 1개당 하루"는 이 문서에 없는 말이니 CDC 명의로 쓰지 않는다.

### 버퍼

이동시간 패딩 비율에 **권위 있는 출처가 없다.** 20~25%·30%·"60%만 계획" 등이 돌아다니지만 전부 블로그 수준이다. 임의 비율을 만들어 쓰지 말고, 대신 실행 가능한 것을 한다:

- 산출한 이동시간에 환승·대기가 이미 포함돼 있는지 확인한다 (Transitous는 포함, OSRM은 미포함)
- 어르신·아이 동행이면 도보 구간에 여유를 명시적으로 얹고 그 사실을 일정에 표시한다
- 예약을 적게 걸어 스왑 여지를 남기는 게 우천·지연에 대한 실질적 대비다

## 5. 국가별 이동 특이사항

**일본** — 도쿄메트로는 2021-03-13 개정으로 전 9개 노선 막차를 평균 10분(최대 16분) 앞당겼고 이건 야간 보수 확보 목적의 항구 조치다. 이후 이동은 택시뿐이고 22:00~05:00은 심야할증 20%가 붙는다. 무기명 Suica·PASMO는 2025-03-01 판매가 재개됐지만 외국인 전용 PASMO PASSPORT는 여전히 미발매다. 전국 10종이 상호이용되나 **IC 에어리어 경계를 넘는 연속 승차는 개찰기에서 막힌다.** JR패스 7일권은 ¥50,000이고 노조미 추가가 ¥4,960이라 도쿄↔교토 왕복만으로는 본전이 안 나온다.

**이탈리아 ZTL** — 카메라 자동단속이고 과태료가 €83~~332인데 **게이트를 통과할 때마다 별건**이다. 외국인 렌터카는 렌터카사 행정수수료 €30~~60가 먼저 카드에 청구되고, 본 과태료는 통지기한 360일 탓에 최장 15개월 뒤에 온다. 밀라노 Area C는 평일 07:30~19:30에 €7.50/일이다.

**런던** — 혼잡통행료 £18(평일 07:00~18:00)과 ULEZ £12.50/일(전 자치구·연중무휴)이 별개로 붙고 외국 등록 차량도 동일하게 적용된다.

**미국** — 통근 대중교통 분담률이 20%를 넘는 도시는 뉴욕 48.7·저지시티 45.1·워싱턴DC 26.6·보스턴 25.3·샌프란시스코 25.0·뉴어크 23.4·시카고 20.5·필라델피아 20.1뿐이고 전 도시가 2015년 대비 하락했다. 그 밖은 렌터카 전제로 짠다. 반대로 뉴욕은 2025년 1월부터 60가 이남 진입에 승용차 피크 $9가 붙는다.

**태국** — TomTom 2025년판 기준 방콕은 10km 이동에 평균 22분 35초다. BTS 막차는 종착역 기준 23:30~~23:50. **Rabbit Card는 BTS·BRT 전용이라 MRT에서 안 되고**, MRT는 컨택리스 카드를 직접 태그한다. 그리고 미터택시가 Grab보다 30~~50% 싸다 — 실롬→수쿰윗이 70~~90바트 대 130~~180바트로, "Grab이 편하지만 조금 비싸다"가 아니라 상시 2배 구조다.

**콜로세움** — 공식 판매처가 2024년 5월 ticketing.colosseo.it으로 바뀌었다. 오래된 가이드를 따르면 비공식 리셀러에 걸린다.
