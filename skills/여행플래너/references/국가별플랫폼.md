# 국가별 지도·리뷰 플랫폼 — 뭘 읽고 뭘 포기할 것인가

각 나라에서 현지인이 실제로 쓰는 지도와 맛집 소스, 그리고 **Claude가 그걸 실제로 읽을 수 있는지**를 실측으로 정리한 문서다. 여행지가 정해지면 일을 시작하기 전에 해당 국가 항목을 먼저 읽는다.

> **⏱️ 실측 기준 시점: 2026년 8월.** 이 문서는 스냅샷이지 항구적 사실이 아니다. 아래 신선도 규칙을 반드시 지킨다.

## ⏱️ 신선도 규칙 — 이 문서는 낡는다

플랫폼은 수시로 죽고, 봇 차단을 강화하고, URL 구조를 바꾼다. **이 문서를 근거로 사용자에게 확정 정보를 주는 순간 그 낡음이 사고가 된다.**

실제로 겪은 사례들이 경고다. Paradise Cove 루아우는 47년 만에 폐업했는데 **가격 페이지가 아직 살아 있어서** 여행사와 블로그가 계속 인용하고 있었다. Quandoo는 2026-09-30 종료 공지를 걸어둔 상태였고, 망고플레이트는 DNS 자체가 사라졌다.

**그래서 이렇게 한다.**

| 정보 종류                              | 신선도 취급                                           |
| :------------------------------------- | :---------------------------------------------------- |
| **접근성 판정**(읽힘/403/빈껍데기)     | 라우팅 힌트로만 쓴다. 실제로 열어보면 바로 확인된다   |
| **점수 척도**(타베로그 3.5=상위 3% 등) | 비교적 안정적. 그대로 신뢰 가능                       |
| **개별 업소 정보**(영업시간·휴무·가격) | 🔴 **이 문서에 없다.** 항상 그 세션에서 새로 확인한다 |
| **서비스 생존 여부**(폐업·종료 예정)   | 🔴 **가장 빨리 낡는다.** 일정에 넣기 전 반드시 재확인 |

**세 가지 실행 규칙**

1. **일정에 들어갈 업소는 예외 없이 이번 세션에서 연다.** 이 문서는 "어디서 찾을지"만 알려주지 "무엇이 있는지"는 알려주지 않는다.
2. **"종료 예정" 표기가 붙은 서비스는 날짜를 지났는지 먼저 본다.** 25절 죽은 것 목록은 작성 시점 기준이다.
3. **판정이 문서와 다르면 문서가 틀린 것이다.** 열어봤더니 403이던 곳이 열리거나 그 반대면, 실제 결과를 따르고 사용자에게 그 사실을 알린다. 여유가 있으면 이 문서를 갱신한다.

**공개용 산출물(가이드·캐러셀·배포물)에 이 DB의 내용을 그대로 옮길 때는 발행 직전 재실측이 필수다.** 내부 조사용과 외부 발행용의 기준이 다르다.

## 🔬 검증 등급 — 항목마다 신뢰도가 다르다

이 문서의 모든 지역이 같은 무게가 아니다. **직접 열어본 곳과 조사만 한 곳을 섞으면 안 된다.**

|      등급       | 뜻                                                          | 취급                                                           |
| :-------------: | :---------------------------------------------------------- | :------------------------------------------------------------- |
| **A 직접 실측** | 실제로 fetch해서 응답을 확인했다                            | 라우팅 근거로 사용 가능                                        |
| **B 조사 기반** | 서브에이전트 조사·문서 확인은 했으나 직접 두들겨보지 않았다 | 🔴 **힌트일 뿐이다.** 첫 fetch로 직접 확인하고 결과를 반영한다 |

| 지역                              |           등급            | 근거                                                                        |
| :-------------------------------- | :-----------------------: | :-------------------------------------------------------------------------- |
| 일본 (1절)                        |           **A**           | 타베로그 `/en/` 랭킹·상세 페이지, Yahoo 乗換案内 응답까지 확인              |
| 한국 (2절)                        |           **A**           | 네이버 계열 차단, 다이닝코드·비짓부산·구석구석 JS 셸, 유튜브 검색 동작 확인 |
| 홍콩·태국·베트남·싱가포르 (5~8절) | **A** (상세 페이지 1건씩) | 접근 가능 여부만 확인. 랭킹 페이지 구조는 미확인                            |
| 미국·캐나다 (12절)                |           **A**           | 하와이 일정 조립에서 실제로 사용                                            |
| **그 외 전 지역**                 |           **B**           | 🔴 서브에이전트 1회 조사 결과이고 **직접 재확인하지 않았다**                |

**B등급 지역 작업을 시작할 때의 첫 동작**은 조사가 아니라 **판정 갱신**이다. 그 지역 대표 소스 하나를 열어보고, 문서와 다르면 실제 결과를 따르고 문서를 고친다. 사용자에게도 "이 지역은 제가 직접 확인해본 적이 없어서 지금 소스부터 확인하겠다"고 밝힌다.

에이전트가 "미검증"이라고 표시한 것 외에도 **에이전트의 판정 자체가 틀렸을 수 있다.** 실제로 한식당 랭킹에서 스니펫과 실측이 충돌한 사례가 있었다. 그때는 잡았지만 못 잡은 게 없다는 보장이 없다.

## 0. 가장 중요한 전제

**리뷰·예약 플랫폼 대부분은 WebFetch로 못 읽는다.** 실측에서 Yelp·TripAdvisor·Michelin·TheFork·OpenTable·Klook·Google Maps·booking.com·agoda가 전부 403이거나 빈 껍데기였다. Reddit·Eater는 도구 레벨에서 막혀 있다.

그래서 이 스킬은 **"플랫폼을 크롤링한다"가 아니라 "뚫리는 소스를 골라 읽고, 막힌 플랫폼은 링크만 넘긴다"** 구조다. 막힌 사이트에 fetch를 시도하면 토큰과 시간만 태운다.

### 뚫리는 소스 등급표

| :------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------- |
| **A — 구조화 데이터가 그대로 나옴**    | **타베로그 `/en/`(일본)** · **Wongnai(태국)** · **Foody.vn(베트남)** · OpenRice(홍콩) · Burpple / Chope(싱가포르) · ifoodie(대만) · Traveloka(인도네시아 액티비티) · 携程 식당리스트(중국) · trip.com(항공·호텔) · Yahoo!乗換案内(일본 교통) | 직접 fetch, 필드 파싱                  |

### 🔴 점수 척도는 나라마다 다르다 — 최대 오답 위험

평점 필터를 국가 공통 로직으로 만들면 안 된다. 같은 "4.1"이 나라마다 전혀 다른 의미다.

| :----------------------------- | :-------- | :----------------------------------------------- | :--------------------------- |

| **Foody.vn** (베트남)          | **10**    | 6점대 평범 · 8점대부터 유의미 · 9점대 상위       | 6.6="보통" 라벨 실측         |

**타베로그 3.5를 "그냥 보통"으로 읽는 게 가장 흔한 사고다.** 5점 척도라고 다 같은 5점 척도가 아니다.

### 💀 DuckDuckGo lite — 죽었다. 시도하지 않는다

```
lite.duckduckgo.com/lite/?q=   ❌ 첫 요청부터 CAPTCHA
html.duckduckgo.com/html/?q=   ❌ 동일
```

**2026-08-06 실측**: HTTP 202, 14,235바이트, 외부 결과 링크 0개. 본문에 `Please complete the following challenge... Select all squares containing a duck`.

🔴 **"15~20회 연속 호출하면 걸린다"는 옛 판정이고, 지금은 첫 요청부터 걸린다.** 이걸 모르면 원인을 오진하고 간격을 두며 재시도를 반복하게 된다. **CAPTCHA는 우회 금지 대상이라 이 경로에는 복구 수단이 없다.** 한 번 걸리면 그 소스는 포기하고 다른 경로로 간다.

**대체 경로**

| 원래 목적                          | 지금 쓰는 것                                            |
| :--------------------------------- | :------------------------------------------------------ |
| 레딧 스레드                        | 🔴 **Bash `old.reddit.com`으로 직접 읽는다.** 아래 참고 |
| 차단 플랫폼 수치(Yelp·TripAdvisor) | WebSearch에 `allowed_domains`를 지정해 스니펫 회수      |
| 미슐랭                             | Wikipedia 3스타 목록                                    |

🔴 **레딧은 막혀 있지 않다.** 예전 판정이 틀렸다 — WebFetch만 막히고 **Bash curl로 `old.reddit.com`은 열린다.** 2026-08-06 실측: `old.reddit.com/r/JapanTravel/search?q=osaka%20food&restrict_sr=on&sort=top` → HTTP 200, 492KB, 검색 결과 178건, 실제 제목 수확(`I spent 108 days in Japan, and this is what I recommend.`). 방법은 `소셜수집.md`에 있다.

r.jina.ai 프록시로 TripAdvisor를 우회하는 것도 실패했다.

### Wikivoyage 사용법

대도시 본문은 잘려서 Eat 섹션이 통째로 사라진다 (파리·로마 실측 실패). **반드시 구역 문서로 접근한다.**

```
https://en.wikivoyage.org/wiki/<City>/<District>
예: /wiki/Rome/Colosseo → 식당명·주소·가격대(€0.50–15)까지 회수
```

## 1. 일본

아시아에서 접근성이 가장 좋다. 열쇠는 타베로그 영문 경로다.

### 🔑 타베로그는 반드시 `/en/` 경로로 호출한다

```
❌ https://tabelog.com/tokyo/A1301/A130101/13002378/       → 403
✅ https://tabelog.com/en/tokyo/A1301/A130101/13002378/    → 완전히 읽힘
✅ https://tabelog.com/en/tokyo/A1301/A130101/rank/        → 지역 랭킹
✅ https://tabelog.com/en/kyoto/A2601/A260201/rank/        → 다른 도시도 동일
```

일본어 경로는 봇차단이고 `/en/`만 열린다. 이 한 줄이 일본 파트 전체를 살린다.

**상세 페이지에서 실제로 뽑히는 필드** (긴자 스시집 실측):

```
점수 3.49 · 리뷰 664건 · 전화 · 주소 · 최기역 + 도보 분(東銀座 5분)
요일별 영업시간 · 정기휴일(월) · 디너예산 ¥8,000–9,999 / 런치예산 ¥1,000–1,999
좌석수 43 · 개인실 유무 · 금연 여부
카드 가능 브랜드(VISA/Master/JCB/AMEX/Diners) · 예약 정책 · 주차
```

일정 설계에 필요한 게 한 페이지에 다 있다. 다른 실측 사례에서는 **"런치는 현금만, 디너는 예약 필수"**가 그대로 나왔다 — 같은 가게라도 시간대에 따라 현금 준비 여부가 갈린다는 뜻이고, 이런 건 추측으로 못 만든다.

### 지역 코드를 찾는 법

URL의 `A1301` 같은 코드는 외우거나 추측하지 않는다. **현(prefecture) 인덱스 페이지가 전체 목록을 준다.**

```
https://tabelog.com/en/tokyo/   → 도쿄 31개 지역 코드가 이름과 함께 전부 나옴
https://tabelog.com/en/osaka/   → 오사카도 동일
```

도쿄 주요 코드 (실측): 긴자·신바시·유라쿠초 A1301 · 도쿄역·니혼바시 A1302 · 시부야·에비스·다이칸야마 A1303 · 신주쿠·요요기 A1304 · 이케부쿠로 A1305 · 하라주쿠·오모테산도·아오야마 A1306 · 롯폰기 A1307 · 아키하바라·간다 A1310 · 우에노 A1311 · 츠키지·오다이바 A1313

세부 구역까지 좁히려면 `A1301/A130101` 처럼 한 단계 더 들어간다. 이것도 상위 지역 페이지에 링크로 나온다.

### ⚠️ 타베로그 점수 척도 — 3.5가 왜 높은 건지

공식 문서(`tabelog.com/en/help/score/`) 기준이다.

| 점수      | 위치                           |
| :-------- | :----------------------------- |
| 4.00 이상 | **상위 약 0.07%**              |
| 3.50–3.99 | **상위 약 3%** ← 이미 "훌륭함" |
| 3.50 미만 | 약 97% (대다수)                |

단순 평균이 아니라 유저 영향력 가중 + 스텔스 마케팅 보정이 들어가고 격주 화요일에 갱신된다. 유료 가맹은 점수에 영향이 없다. 실측 랭킹 1위가 긴자 4.61, 교토 가와라마치 4.52이므로 **4.5면 전국구 최상위**다.

**3.5를 "그냥 보통"으로 읽으면 안 된다.** 5점 척도의 다른 나라 감각을 그대로 가져오면 일본 맛집을 전부 걸러내게 된다.

### 실제로 작동하는 경로 — 유튜브가 본체다

한국은 **"플랫폼을 읽는다"가 아니라 "유튜브를 읽는다"** 로 접근을 바꿔야 한다. 네이버 차단은 웹 도구의 문제이고 **`yt-dlp`는 그 차단과 무관하다.** 한국 여행 유튜브는 세계 최대급으로 두껍기 때문에 이게 손실이 아니라 오히려 강한 경로다.

2026-08-06 실측 — `yt-dlp "ytsearch3:제주 흑돼지 맛집 로컬"`이 즉시 반환한 것:

```
스타밥집: 배우 구본승이 엄선한 제주 맛집! 흑돼지 맛의 신세계 [2TV 생생정보] | KBS 251121 방송
제주도 흑돼지 1티어급 추천맛집 "여긴 진짜 모르는 사람 없었으면 좋겠다"
제주 전통 육식 올스타전 : 원조와 근본 고기 식당으로만 가득 채운 2박 3일 (…)
```

**국내 조사 순서 (이대로 실행한다)**

1. **유튜브에서 후보 발굴** — `yt-dlp "ytsearch8:<지역> <카테고리> 맛집"`. 챕터와 설명란에서 상호를 뽑는다. 한국 여행 영상은 챕터에 상호를 그대로 박아두는 관행이 있어 수확률이 높다
2. **인스타 캡션 스니펫** — `site:instagram.com <지역> 맛집` 검색. 캡션 전문이 스니펫에 실린다
3. **다이닝코드 별점은 검색 스니펫으로만** — `site:diningcode.com <지역> 맛집` 스니펫에 상호와 별점이 실린다 (최가네 4.4★ 등). 페이지 자체는 못 연다
4. **확정은 개별 공식 소스로** — 가게 공식 인스타·홈페이지·전화. 영업시간과 휴무는 여기서 확정한다
5. **구글맵은 브라우저 도구로** — 국내도 영업시간과 혼잡 곡선은 읽힌다. 다만 **경로 탐색 품질은 네이버·카카오보다 확실히 낮다**
6. **영어 위키보이저**는 지역 구조 파악에 쓴다 — `en.wikivoyage.org/wiki/Jeju`는 43,481자 실콘텐츠가 나온다 (한국어판은 없다)

**WebSearch 예산이 곧 한국 리서치의 한도**라는 점은 그대로다. 그래서 1번(유튜브, 예산 소모 없음)을 먼저 돌리고 검색은 확정 단계에 아낀다.

**지도 점유율** (2025년 2월 MAU): 네이버지도 2,650만 / T맵 1,440만 / 카카오맵 1,060만 / 구글맵 880만. 구글·애플의 상세 지도 데이터 반출이 안보 규정으로 반복 지연되면서 국내 사업자가 반사이익을 보는 구조다. 애플맵은 횡단보도·계단·지하도 정보가 빠져 있다.

→ **한국 여행 일정은 사용자 본인이 네이버지도로 확인하는 걸 전제로 짠다.** Claude가 못 읽는다는 사실을 숨기지 말고 밝힌다.

```
✅ https://www.wongnai.com/restaurants/<id>
✅ https://www.wongnai.com/listings/<슬러그>     ← 큐레이션 리스트
```

**뽑히는 필드**: 상호 · 4.1/5 · 리뷰 29건 / 평점 32건 · 가격대 `฿฿฿฿ (501–1,000 THB/인)` · **건물·층까지 나오는 주소** · 영업시간 · 전화 · 요리 카테고리 · **메뉴명 + 개별 가격** · 배달/매장식사 여부 · **카테고리 내 순위**(이탈리안 1,919곳 중 258위)

**점수 척도** — 5점 만점. 방콕 100대 맛집 큐레이션 리스트의 실측 분포가 3.9~4.6이다(유명 국수집이 3.9/776리뷰). **유명 맛집도 4점대 초반이 흔하므로 4.0+면 양호, 4.5+면 최상위**로 읽는다. Wongnai 공식 임계값 문서는 미검증이다.

주소가 건물·층 단위로 나오므로 지도를 못 읽어도 위치 특정이 된다. 예약 필드는 페이지에서 관측되지 않았고 예약 문화·결제는 미검증이다.

## 7. 베트남

**Foody.vn이 살아 있고 완전히 읽힌다. 다만 척도가 10점제인 게 함정이다.**

```
✅ https://www.foody.vn/ho-chi-minh/<슬러그>
✅ https://www.foody.vn/ho-chi-minh/quan-an        ← 리스트 (호치민 84,379건)

```

**뽑히는 필드**: 상호 · **6.6/10 + 사이트가 붙인 라벨** · **5개 세부축**(공간 7.4 / 품질 6.9 / 위치 6.8 / 서비스 6.3 / 가격 5.9) · 리뷰 수 · 가격대 50,000~200,000đ · 주소 · 영업시간 + 라스트오더 · **시설 태그**(와이파이·에어컨·포장·카드결제 가능·주차·룸)

### 🔴 점수 척도 — 10점 만점이다

5점 만점으로 오독하면 전부 틀린다. 실측 근거가 있는 건 **6.6 = "Trung bình(보통)"** 라벨이고, 리스트 관측 분포는 7.0 / 6.9 / 8.6 / 9.7 / 9.8로 상단이 9점대까지 실제로 존재한다. **6점대는 평범, 8점대부터 유의미, 9점대가 상위**로 읽는다. "8.0이 기준선"이라는 공식 임계값은 미검증이다.

## 16. 스페인

**실무** — 팁은 잔돈 반올림 수준이고 74%가 5% 미만을 낸다. **저녁 20:30~23:00**이 실제이고 점심은 14:00~15:30, 오후 간식(merienda)이 18시경이다. 8월 휴가 폐점이 일반적이라 마드리드 매체들이 매년 "8월에 안 닫는 식당" 가이드를 낼 정도다.
