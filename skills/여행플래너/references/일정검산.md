# 일정 검산 — 이 일정이 시간상 실제로 가능한가

일정표는 그럴듯해 보이기 쉽다. 아침에 A, 점심 B, 오후 C, 저녁 D — 읽으면 완벽한데 실제로 가보면 C에서 이미 해가 진다.

**대부분의 AI 일정표가 무너지는 지점이 여기다.** 장소는 잘 골랐는데 이동시간을 안 더했거나, 폐관 시각을 안 봤거나, 막차를 놓치는 구성이다.

`실조사.md`의 커버리지 체크는 **빠진 게 없는지**를 본다. 이 문서는 **시간이 실제로 맞는지**를 본다. 일정을 사용자에게 내밀기 전에 반드시 돌린다.

## 0. 🔴 이 검산의 한계 — 먼저 읽는다

**검산은 일관성 검사지 사실 검증이 아니다.** 입력이 틀리면 틀린 입력으로 계산해서 "통과"라고 답한다.

| 잡는다                           | 못 잡는다                                      |
| :------------------------------- | :--------------------------------------------- |
| 목요일 휴무 가게를 목요일에 넣음 | 그 가게가 목요일 휴무라는 **정보 자체가 틀림** |
| 폐관 30분 전 도착                | 폐관 시각을 **잘못 읽음**                      |
| 막차 이후 복귀                   | 그 노선이 **작년에 없어짐**                    |
| 하루 5곳으로 상한 초과           | 그 스팟이 **이미 폐업**                        |

실제 사례: 하와이 하나우마베이를 "예약 필수"로 넣었고 검산은 통과했다. 나중에 **당일 약 25% 배정**이 있다는 걸 알고 "권장"으로 고쳤다. 전제가 틀린 것이라 시간축 계산으로는 잡힐 수가 없었다.

**따라서 검산 통과를 "검증됐다"고 보고하지 않는다.** 사실 쪽은 `납품기준.md` 1절의 사실 등급이 담당한다. 검산 전에 **모든 값이 실측 등급인지 먼저 확인**하는 게 이 문서의 전제다.

## 1. 하루를 분 단위로 돌린다

각 날짜마다 시작 시각부터 끝까지 누적 계산한다.

```
현재시각 = 출발시각
각 스팟마다:
    현재시각 += 이동시간(직전 위치 → 이 스팟)
    도착시각 = 현재시각
    [검사 항목 실행]
    현재시각 += 체류시간
    출발시각 = 현재시각
마지막: 숙소 복귀 시각 = 현재시각 + 이동시간(마지막 스팟 → 숙소)
```

이동시간은 `동선설계.md`의 폴백 사다리로 구한 값을 쓰고, **타당성 필터를 통과한 값만** 쓴다.

## 2. 검사 항목

각 스팟에 도착할 때마다 확인한다. 하나라도 걸리면 그 날은 재설계 대상이다.

| #   | 검사                 | 실패 조건                                                           |
| :-- | :------------------- | :------------------------------------------------------------------ |
| 1   | **개장 전 도착**     | 도착시각 < 개장시각 → 문 앞에서 대기                                |
| 2   | **유효 폐관**        | 도착시각 > 유효 폐관 → 제대로 못 본다 (유형별 기준은 2-1절)         |
| 3   | **정기휴무**         | 그 요일이 휴무일 → 헛걸음                                           |
| 4   | **주방 닫힘**        | 식사 배정 시각이 브레이크타임 안 → 밥 못 먹는다                     |
| 5   | **막차**             | 숙소 복귀 시각 > 막차 시각 → 택시비 또는 발묶임                     |
| 6   | **예약 슬롯**        | 슬롯형(15분·30분) 예약 시각과 도착 시각 불일치                      |
| 7   | **하루 총량**        | 아래 3절                                                            |
| 8   | **공항 도착 마감**   | (마지막 날) 그 지역을 떠나는 시각 > 하드 마감 → **비행기를 놓친다** |
| 9   | **동행자 제약 카드** | 카드의 어느 한 줄이라도 위반 → 아래 3-1절                           |

**2번이 가장 자주 걸린다.** 표기 폐관 시각을 그대로 도착 마감으로 쓰면 안 된다.

### 2-1. 유효 폐관은 유형별로 다르다 — 전부에 −60분을 걸지 않는다

예전에는 모든 스팟에 일괄 −60분을 걸었다. 그런데 **그 60분에는 출처가 없었고**, 같은 문서 마지막 절이 "출처 없는 숫자를 만들어 쓰지 말 것"을 금지 항목으로 두고 있어 자기모순이었다. 게다가 식당·시장·거리에까지 걸려서 하루 3곳이 근거 없이 2곳으로 눌렸다.

| 유형 | 유효 폐관 | 등급 |
| :-- | :-- | :--: |
| **명소·박물관** — 최종 입장·티켓 마감이 표기된 곳 | **그 표기값을 쓴다** | 실측 |
| **명소·박물관** — 표기를 못 찾은 곳 | 폐관 −60분 | **추정** |
| **식당** | 라스트오더 시각 (표기 없으면 폐관 −30분) | 실측 우선 |
| **시장·거리·전망대·공원** | 적용하지 않는다 — 마감 개념이 다르다 | — |

- **추정 등급인 값은 사용자에게 "대략"으로 보여준다**(`납품기준.md` 1절). 실측값에는 붙이지 않는다 — 그 차이가 신뢰의 근거다
- 최종 입장 시각은 공식 사이트에 대개 적혀 있다. **한 번 열어보면 추정을 실측으로 바꿀 수 있다**
- 이 값은 회귀식 과대추정과 **같은 방향의 편향**이라 겹치면 하루가 이중으로 깎인다. 하루 배치가 빡빡하게 나오면 둘 중 어느 쪽이 추정인지 먼저 본다

**8번은 마지막 날에만 걸리지만 실패 비용이 가장 크다.** 하드 마감은 `숙소역산.md` 2-1절에서 역산한 값이다. 체크아웃 시각과 짐 보관 방식이 정해지지 않았으면 8번을 검사할 수 없다 — 그 상태로 마지막 날을 납품하지 않는다.

## 3. 하루 총량 점검

개별 스팟이 다 통과해도 하루 총계가 무리일 수 있다.

```
이동시간 합    = 구간별 이동시간 총합
도보 거리 합   = 도보 구간의 직선거리 총합 × 1.36 (우회계수)
활동 시간      = 첫 출발 ~ 숙소 복귀
스팟 수        = 그날 방문지 개수
```

**동행자 상한과 대조한다.** `여행상담.md`에서 잡은 조건이 여기서 검산된다.

- 스팟 수가 **기본 3곳·상한 4곳**을 넘는가 (어르신·아이 동행이면 2~3곳)
- 어르신 동행인데 **한 번에 20~30분 넘는 도보 구간**이 있는가
- 활동 시간이 너무 긴가 — 어르신·아이면 저녁을 이르게 잡았는지

⚠️ **하루 총 도보량의 정확한 상한선은 신뢰할 출처를 찾지 못했다.** 임의 숫자를 만들어 쓰지 말고, 계산한 값을 **사용자에게 보여주고 판단을 받는다**: "이 날은 도보가 총 4km 정도 나오는데 부모님 괜찮으실까요?"

## 3-1. ★ 동행자 제약 카드 — 서술이 아니라 검사 항목으로

이 스킬의 차별점은 "동행자에 따라 일정이 달라진다"인데, **검사표에 동행자 항목이 없으면 그 차별점은 검증되지 않는다.** 실제로 4세 아이의 낮잠 시간(13~15시)에 야외 스팟이 박힌 일정도 예전 검사표는 통과시켰다.

그래서 **상담 직후에 제약을 카드로 고정**하고, 검산에서 그 카드를 한 줄씩 검사한다. 서술형("어르신이면 무리하지 않게")은 검사가 안 된다. **시각과 숫자로 적는다.**

**카드는 `$TRIP_DIR/여행노트.md`에 쓰고** 일정이 바뀔 때마다 이 카드로 재검사한다.

### 카드 예시

```
[동행자 제약 카드]  아이 4세 + 부모 2
- 13:00~15:00  낮잠 블록 — 숙소 또는 이동만. 야외·대기 금지
- 대기 상한     15분 (초과 예상 스팟은 예약 필수 또는 제외)
- 유모차        계단 전용 환승역 회피. 엘리베이터 확인된 역만
- 저녁          18:30 이전 착석
- 스팟 수       하루 3곳
```

```
[동행자 제약 카드]  부모님(70대) 2 + 본인 1
- 연속 도보     25분 이내 (초과 구간은 택시로 대체)
- 좌식          불가 — 테이블석 확인된 곳만
- 저녁          18:00 이전 착석
- 스팟 수       하루 3곳
- 화장실        오전·오후 각 1회 이상 동선에 포함
```

### 검사 방법

각 줄을 **그날 시간표에 대고 직접 대조한다.** "반영했다"는 느낌이 아니라 위반 여부를 판정한다.

```
□ 시간 블록(낮잠·이른 저녁)을 침범한 배정이 있는가
□ 대기 상한을 넘길 것으로 조사된 스팟이 들어갔는가
□ 이동 제약(계단·연속 도보)을 어긴 구간이 있는가
□ 좌식·1인 입장·최소 인원 같은 입장 조건을 확인하지 않은 곳이 있는가
□ 스팟 수 상한을 넘었는가
```

🔴 **확인 못 한 조건은 통과가 아니라 `미확인`이다.** 좌식 여부를 못 찾았으면 "괜찮을 것"으로 넘기지 말고 아티팩트에 `좌식 미확인` 태그를 노출해 현장에서 대비하게 한다. 숨기는 것보다 낫다.

## 4. 체류시간 기본값

이동시간과 달리 체류시간은 조회할 데가 없다. 아래를 출발점으로 쓰되 **실제 정보가 있으면 그걸 우선한다.**

| 유형               | 기본 체류   | 근거·비고                                                              |
| :----------------- | :---------- | :--------------------------------------------------------------------- |
| 대형 박물관·미술관 | 1.5~2시간   | 관람객 집중이 약 30분 후 하강하고, 2~3시간이 한계라는 게 반복 관측된다 |
| 소규모 전시·기념관 | 45분~1시간  |                                                                        |
| 사원·성·궁         | 1시간       | 규모에 따라 조정                                                       |
| 전망대             | 45분        | 대기 별도                                                              |
| 시장·상점가        | 1~1.5시간   | 쇼핑 의도가 있으면 늘린다                                              |
| 식사               | 1~1.5시간   | 대기 시간 별도. 인기 식당은 대기를 따로 얹는다                         |
| 카페·휴식          | 45분        | 어르신 동행이면 일정에 명시적으로 넣는다                               |
| 공원·산책          | 1시간       |                                                                        |
| 테마파크           | 반나절~하루 | 단독 배치                                                              |

**슬롯형 예약은 정해진 시간을 그대로 쓴다** — 최후의 만찬은 15분, 알람브라 나스르 궁전은 30분이다.

**대기 시간을 빼먹지 않는다.** 유튜브·레딧 조사에서 "줄이 길다"는 언급이 있었으면 그 정보를 여기 반영한다.

## 5. 실패했을 때 — 뭘 뺄 것인가

검산에서 걸리면 순서대로 조정한다.

1. **"선택" 항목을 먼저 뺀다** — 확정 아닌 것부터
2. **체류시간을 줄인다** — 다만 박물관을 45분으로 줄이는 건 안 가느니만 못하다
3. **순서를 바꾼다** — 폐관이 이른 곳을 앞으로
4. **다른 날로 옮긴다** — 같은 권역의 다른 날이 여유 있으면
5. **스팟 하나를 뺀다** — 여기까지 왔으면 뺀다. 다 넣고 무너지는 것보다 낫다

**임의로 빼지 말고 사용자에게 알린다.** "이 날은 네 군데가 안 들어가서 한 곳을 다음날로 옮겼어요"라고 말하고, 어느 걸 뺄지 선택지를 주는 게 낫다.

## 6. 사용자에게 보여주는 법

검산 결과를 **하루 한 줄 요약**으로 보여준다. 이게 "제대로 계산했다"는 증거다.

> **3일차** — 09:00 출발 → 숙소 복귀 19:40 · 이동 1시간 50분 · 도보 약 3.2km · 3곳
> ⚠️ 저녁 식당이 20:30 라스트오더라 18:50까지는 도착해야 합니다. 그 앞 일정을 20분 당겼어요.

문제가 있었고 고쳤으면 **고쳤다는 사실을 말한다.** 조용히 고치면 사용자는 그 일정이 원래 그랬던 줄 안다.

## 7. 하지 말 것

- **검산 없이 일정을 내미는 것**
- 이동시간을 눈대중으로 넣는 것 — 반드시 산출값을 쓴다
- 폐관 시각을 그대로 도착 마감으로 쓰는 것 (유효 폐관은 2-1절 유형별로)
- 대기 시간을 0으로 두는 것
- 하루 도보량 상한 같은 **출처 없는 숫자를 만들어 쓰는 것** — 계산해서 보여주고 사용자가 판단하게 한다
- 검산 실패를 조용히 무마하는 것
