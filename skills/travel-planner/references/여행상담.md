# 여행 상담 — 가이드처럼 묻고, 그 사람의 여행을 짜는 법

이 스킬의 본체는 데이터가 아니라 **상담**이다. 같은 도시라도 누구랑 가느냐에 따라 완전히 다른 일정이 나와야 한다. 부모님 모시고 가는 도쿄와 친구들끼리 가는 도쿄는 겹치는 게 거의 없다.

**여행지가 같으면 일정도 같아지는 순간, 이 스킬은 실패한 것이다.**

## 0. 대원칙

1. **심문하지 않는다.** 한 번에 묻는 건 최대 3~4개. 나머지는 대화하면서 자연스럽게 채운다.
2. **이미 나온 건 절대 다시 묻지 않는다.** 사용자가 "부모님이랑"이라고 한 걸 나중에 "몇 분이서 가세요?"라고 물으면 상담이 아니라 폼 작성이다.
3. **빈 질문보다 구체물을 내민다.** "어떤 스타일 좋아하세요?"는 답하기 어렵다. 1일차 초안을 보여주고 "이 페이스 괜찮으세요?"가 열 배 쉽다.
4. **왜 이렇게 짰는지 한 줄씩 말한다.** 근거 없는 일정은 사용자가 못 고친다.
5. **묻지 않은 것도 경고한다.** 진짜 가이드는 손님이 모르는 위험을 먼저 말한다.

## 1. 인터뷰는 한 번이 아니라 라운드다

**질문 총량은 많아야 하고, 한 라운드의 질문 수는 적어야 한다.** 이 둘은 모순이 아니다. 3~4개씩 나눠 여러 번 물으면 사용자는 심문당한다고 느끼지 않으면서 답을 많이 준다. 한 번에 여덟 개를 던지는 순간 상담이 폼 작성이 된다.

라운드는 이렇게 간다.

```
1차  시작 전   누구와 · 몇 명 관계 · 언제 며칠 · 어디 · 뭘 제일 하고 싶은지
                + 이동수단(렌터카냐) + 이미 잡아둔 것(숙소 링크·예약)
2차  조사 후   찾아온 후보를 들고 고르게 한다 (식당·관광·쇼핑)
3차  초안 후   1일차를 보여주고 페이스·순서 반응을 받는다
이후  계속     사용자가 빼고 더하는 것이 답변보다 정확하다 (5절)
```

### 1차 인터뷰 — 이것만 알면 시작할 수 있다

처음에 확보할 건 다섯이다. 그 이상 묻지 않는다.

| 질문                                        | 왜 필요한가                                                        |
| :------------------------------------------ | :----------------------------------------------------------------- |
| **누구와 가세요?**                          | 일정 전체를 지배한다. 아래 2번 참고                                |
| **몇 분이서, 서로 어떤 관계세요?**          | 인원이 예약 가능 여부를 가르고, 관계가 페이스를 가른다             |
| **언제, 며칠?**                             | 요일이 휴무일·혼잡도를 결정한다. 날짜 없이는 아무것도 확정 못 한다 |
| **어디로?** (정해졌는지)                    | 안 정해졌으면 먼저 정하는 게 상담이다                              |
| **이번 여행에서 제일 하고 싶은 게 뭐예요?** | 무게중심. 맛집인지 관광인지 쉬는 건지                              |

🔴 **이동수단은 초안 전에 반드시 확정한다.** "렌터카 쓰실 건가요, 대중교통이세요?" 이 한 줄이 동선·숙소 위치·하루 스팟 수·주차비를 전부 뒤집는다. 나중에 물으면 짠 걸 다 버려야 한다. 1차에서 못 물었으면 **조사를 시작하기 전에** 묻는다.

🔴 **이미 잡아둔 게 있는지 먼저 묻는다. 특히 숙소.** 숙소가 정해져 있으면 동선 전체가 그 좌표 기준으로 바뀌므로, 추천을 시작하기 전에 물어야 한다. 안 묻고 추천부터 하면 이미 예약한 사람에게 쓸모없는 표를 내미는 꼴이 된다.

> "숙소는 제가 동네부터 좁혀서 후보를 뽑아드릴게요. 혹시 원하시는 곳이나 미리 예약해두신 데가 있으면 링크 하나 던져주세요. 있으면 그 위치 기준으로 동선을 짜겠습니다."

같은 방식으로 **이미 예약한 식당·액티비티·기차표**가 있는지도 묻는다. 링크나 예약 확인 메일을 그대로 받으면 시각과 인원까지 뽑아 일정에 고정한다.

**뒤로 미룰 것**: 예산 상세, 항공편, 식이 제한. 이건 필요해지는 시점에 묻는다. 처음부터 다 물으면 사용자가 지친다.

다만 사용자가 **먼저 준 정보는 즉시 활용**한다. 항공권을 던졌으면 터미널과 첫날 밤 제약을 바로 계산해서 보여준다. 그게 "일 잘한다"는 신호다.

### 1-1. 상담 원장 — G5를 집행하는 파일 ★

**"계속 물어봐라"는 규칙으로는 안 지켜진다.** 세션이 길어지면 안 물어본 게 뭔지 자기도 모르게 된다. 그래서 **세는 파일**로 만든다.

상담을 시작하는 순간 `$TRIP_DIR/여행노트.md` 맨 위에 이 표를 만든다. **12행 고정이고 행을 지우지 않는다.**

```
[상담 원장]  갱신 <날짜>

| 항목           | 값 | 라운드 |
| :------------- | :- | :----- |
| 동행자         |    |        |
| 인원·관계      |    |        |
| 날짜·박수      |    |        |
| 목적지         |    |        |
| 무게중심       |    |        |
| 이동수단       |    |        |
| 기예약         |    |        |
| 페이스         |    |        |
| 예산 감각      |    |        |
| 식이·거동      |    |        |
| 식당 선택      |    |        |
| 예약 필요 항목 |    |        |
```

**빈칸만 금지다.** 값을 못 받았으면 `해당없음`(제약이 없음) 또는 `사용자 위임`("알아서 해줘")을 쓴다. 이 둘도 채워진 것으로 친다. 원장은 사용자를 붙잡아두는 장치가 아니라 **안 물어본 걸 세는 장치**다.

집행 지점은 셋이다.

1. **매 턴 끝** — 빈칸을 보고 **1~3개**를 묻는다. 조사 중이든 조립 중이든 마찬가지다. 다 찼으면 안 묻는다
2. **조립 직전(SKILL.md 5절)** — 원장을 다시 열어 빈칸을 센다. 하나라도 비어 있으면 조립하지 않고 그 항목을 먼저 묻는다
3. **납품 직전** — 완료 체크리스트에서 다시 센다 (`납품기준.md` 3절)

값이 바뀌면 **덮어쓰고 갱신일을 고친다.** "생각보다 잘 걸으시네요" 같은 말이 나오면 페이스 행을 바꾸고 남은 날을 다시 검산한다.

### 1-2. 질문 문장 은행 — 그대로 써도 되는 문장

빈 질문을 만들지 말고 여기서 꺼내 쓴다. **한 라운드 3~4개**를 지킨다.

| 원장 항목          | 물어보는 문장                                                                                                                                                     |
| :----------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **동행자**         | 누구랑 가세요?                                                                                                                                                    |
| **인원·관계**      | 몇 분이서 가시고, 서로 어떤 관계세요? 부모님이신지 친구분들이신지에 따라 짜는 게 많이 달라져서요                                                                  |
| **날짜·박수**      | 언제 가시고 몇 박이세요? 요일이 정해져야 휴무를 볼 수 있어요                                                                                                      |
| **목적지**         | 도시는 정하셨어요?                                                                                                                                                |
| **무게중심**       | 이번 여행에서 제일 하고 싶은 게 뭐예요? 맛집인지 관광인지 그냥 푹 쉬는 건지                                                                                       |
| **이동수단**       | 렌터카 쓰실 건가요, 대중교통이세요? 이게 동선이랑 숙소 위치를 완전히 바꿔서 먼저 여쭤요                                                                           |
| **기예약**         | 숙소는 제가 동네부터 좁혀서 후보를 뽑아드릴게요. 혹시 원하시는 곳이나 미리 예약해두신 데가 있으면 링크 하나 던져주세요. 있으면 그 위치 기준으로 동선을 짜겠습니다 |
| **기예약 (추가)**  | 식당이나 기차표, 액티비티 중에 이미 잡아두신 게 있으세요? 예약 확인 메일 그대로 주셔도 됩니다                                                                     |
| **페이스**         | 하루에 서너 군데 부지런히 도는 편이 좋으세요, 두 군데 정도 여유 있게가 좋으세요?                                                                                  |
| **예산 감각**      | 저녁 한 끼 기준으로 어느 정도 생각하세요?                                                                                                                         |
| **식이·거동**      | 못 드시는 거나 알레르기 있으세요? 걷는 게 불편하신 분은요?                                                                                                        |
| **식당 선택**      | 저녁 후보 여덟 곳 찾았어요. 오코노미야키 둘, 쿠시카츠 둘, 라멘 둘, 스시 둘. 세 밤이니까 세 개만 고르시면 되는데 뭐가 제일 당기세요?                               |
| **예약 필요 항목** | 여긴 예약을 미리 잡아야 하는 곳이에요. 넣을까요? 넣으면 그날 다른 걸 하나 빼야 합니다                                                                             |

**묻는 방식 규칙**

- 🔴 **빈 질문 금지.** "어떤 스타일 좋아하세요?"는 답하기 어렵다. 2택으로 주거나 실물 후보를 내민다
- 🔴 **왜 묻는지 반 줄을 붙인다.** "이게 동선을 바꿔서요" 한 마디가 심문을 상담으로 바꾼다
- 🔴 **이미 답한 걸 다시 묻지 않는다.** 묻기 전에 원장을 본다. 이게 원장의 두 번째 용도다
- 답이 `알아서 해줘`면 되묻지 말고 **`사용자 위임`으로 채우고 기본값으로 진행한다**(4절)

### 1-3. 2차 인터뷰 — 후보를 들고 다시 묻는다 ★

**조사가 끝났는데 바로 일정을 조립하면 상담의 절반을 버리는 것이다.** 이 시점의 질문이 1차보다 훨씬 정확한 답을 받는다. 사용자가 빈 질문이 아니라 **실물 후보**를 보고 답하기 때문이다.

조사에서 필요량의 1.5~2배를 찾아뒀으므로(`실조사.md`) 그 초과분이 이 라운드의 재료다.

**식당** — 이게 가장 반응이 좋다. 카테고리별로 묶어 내민다.

> "오사카 저녁 후보 여덟 곳 찾았어요. 오코노미야키 두 곳, 쿠시카츠 두 곳, 라멘 두 곳, 스시 두 곳. 세 밤이니까 세 개만 고르시면 되는데, 뭐가 제일 당기세요?
> 참고로 쿠시카츠 A는 목요일 휴무라 목요일에는 못 넣고, 스시 B는 현금만 받습니다."

- **가격대·대기·결제수단·휴무를 후보 옆에 같이 붙인다.** 고를 때 필요한 정보를 그때 다 준다
- 사용자가 고르지 않은 것도 버리지 않는다. **여행 중 모드의 후보 풀**이 된다(`SKILL.md` 8절)
- "다 좋아요"라고 하면 되묻지 말고 **동선 기준으로 배정하고 밝힌다**

**관광** — 필수와 선택을 나눠 묻는다.

> "여기는 반나절이 통째로 들어가는 곳이에요. 넣으면 그날 다른 걸 하나 빼야 하는데, 넣을까요?"

**쇼핑·액티비티** — 살 것이 있는지, 예약이 필요한 걸 할 생각인지. 예약 필요 항목은 **하루 한 개까지**라 초안 전에 알아야 한다.

이 라운드에서도 **한 번에 3~4개**를 지킨다. 식당 묶음 하나가 질문 하나다.

## 2. 동행자 — 여기서 일정의 8할이 갈린다

누구와 가는지에 따라 **하루 스팟 수, 이동 수단, 식당 종류, 숙소 위치, 시작 시각**이 전부 바뀐다.

### 부모님·어르신 동행

- **하루 2~3곳.** 4곳은 무리다. 이동 사이에 반드시 앉는 시간
- **도보 상한을 명시적으로 잡는다.** 한 번에 20~30분, 하루 총량도 관리. 왕복 1시간 넘는 스팟은 경고를 붙이거나 뺀다
- **계단·환승을 피한다.** 엘리베이터 있는 역, 환승 적은 노선. 지도상 거리보다 이게 중요하다
- **화장실·앉을 곳**을 동선에 넣는다
- **저녁을 이르게.** 늦은 저녁은 다음날을 망친다
- **음식 백업 필수.** 현지식이 안 맞을 때 먹을 수 있는 곳을 하루 하나씩 확보
- **아티팩트 글자 크기 토글**을 반드시 안내

### 어린아이 동행

- **낮잠 시간이 일정의 축이다.** 오후 1~3시에 이동이나 숙소 복귀를 배치
- **유모차 동선** — 계단, 자갈길, 좁은 골목은 지옥이다
- **대기를 못 견딘다.** 줄 서는 맛집은 예약이 되거나 오픈런이 가능할 때만
- **기저귀 갈 곳, 키즈 메뉴, 유아 의자** 확인
- 하루 스팟 수는 어르신과 비슷하게 줄인다

### 커플

- **저녁 한 끼는 특별하게.** 예약이 필요한 곳을 하나 잡고 그날 동선을 거기 맞춘다
- **사진 스팟**을 시간대까지 고려해 배치 (일몰, 야경)
- 아침을 늦게 시작해도 된다 — 오히려 빡빡하면 싸운다
- 둘만의 시간이 나오게 이동을 줄인다

### 친구들

- **밤 일정이 있다.** 술집·야시장·클럽. 그래서 다음날 아침이 늦어진다 — 이걸 반영해서 짠다
- **액티비티 비중**이 높다
- 취향이 갈릴 수 있으니 **선택 항목을 넉넉히** 두고 현장에서 나뉘게 한다
- 예산 감각이 다를 수 있어 가격대를 표시해 둔다

### 혼자

- **카운터석·1인 가능 여부**를 확인한다. 2인 이상만 받는 곳이 꽤 있다
- **야간 안전**을 숙소 위치와 귀가 동선에서 챙긴다
- 일정을 느슨하게 — 혼자면 즉흥이 가능한 게 장점이다
- 예약이 거절될 수 있는 파인다이닝은 미리 확인

### 3대(조부모+부모+아이)

**가장 어렵다.** 어르신 제약과 아이 제약이 동시에 걸린다.

- 두 제약의 **교집합이 아니라 합집합**으로 잡는다 (더 보수적으로)
- 하루 2곳, 숙소를 중심으로 방사형 동선
- **분리 옵션**을 만든다 — 어른팀은 A, 아이팀은 B로 나뉘었다 합치는 구간

### 회사·단체

- 인원이 많으면 **예약 가능 여부가 첫 필터**다. 8인 이상 받는 식당은 확 줄어든다
- 이동 수단을 먼저 정한다 (전세버스 여부)
- 자유시간 블록을 명시적으로 넣는다

### ★ 2-1. 상담이 끝나면 제약 카드를 만든다

동행자 조건을 머릿속에만 두면 조립할 때 새어나간다. **상담 직후 바로 카드로 고정해 `$TRIP_DIR/여행노트.md`에 쓴다.**

핵심은 **시각과 숫자로 적는 것**이다. "어르신이라 무리하지 않게"는 검사가 안 되고, "연속 도보 25분 이내 · 저녁 18:00 이전 착석"은 검사가 된다. 이 카드가 `일정검산.md` 3-1절에서 검사 항목 9번으로 그대로 쓰인다.

```
[동행자 제약 카드]  아이 4세 + 부모 2
- 13:00~15:00  낮잠 블록 — 숙소 또는 이동만. 야외·대기 금지
- 대기 상한     15분
- 유모차        계단 전용 환승역 회피
- 저녁          18:30 이전 착석
- 스팟 수       하루 3곳
```

여행 도중 사용자가 조건을 바꾸면(예: "생각보다 잘 걸으시네요") **카드를 갱신하고 남은 날을 다시 검산한다.**

## 3. 여행 스타일 — 물어보는 법

추상적으로 묻지 말고 **선택지로 준다.**

❌ "어떤 여행 스타일 좋아하세요?"
⭕ "하루에 3~4군데 부지런히 도는 편이 좋으세요, 아니면 2군데 정도 여유 있게가 좋으세요?"

확보할 축:

| 축               | 물어보는 법                                                                                |
| :--------------- | :----------------------------------------------------------------------------------------- |
| **페이스**       | "부지런히 vs 여유롭게" 2택                                                                 |
| **무게중심**     | "이번 여행 하이라이트가 맛집이면 좋겠어요, 관광지면 좋겠어요, 아니면 그냥 푹 쉬는 거예요?" |
| **유명 vs 로컬** | "유명한 데는 웬만큼 가보셨어요? 아니면 첫 방문이라 대표적인 곳 위주가 좋을까요?"           |
| **예산 감각**    | 직접 묻기보다 "저녁 한 끼 기준으로 어느 정도 생각하세요?"                                  |
| **이동**         | 렌터카인지 대중교통인지 — 이게 동선 설계를 완전히 바꾼다                                   |

**한 번에 다 묻지 않는다.** 페이스와 무게중심 둘만 먼저 잡아도 초안을 만들 수 있다.

## 4. "알아서 해줘"에 대응하는 법

가장 흔한 응답이고, 여기서 대부분의 AI가 실패한다. **되묻지 마라.**

**기본 프로필로 1일차만 짜서 보여준다.**

```
기본값 (사용자 정보가 없을 때):
  페이스     하루 3곳
  무게중심   관광 2 : 식사 2 (점심·저녁 배정)
  시작       09:00~09:30
  유명도     첫 방문 가정 → 대표 스팟 위주
  예산       중간대
```

그리고 이렇게 말한다.

> "일단 1일차를 이렇게 잡아봤어요. 아침에 A 갔다가 근처에서 점심, 오후에 B, 저녁은 C. 이 정도 페이스면 괜찮으세요? 더 넣어도 되고 하나 빼도 돼요."

구체물에 대한 반응은 쉽게 나온다. "좀 빡빡한데요" 한 마디면 페이스 축이 확정된다.

## 5. 선호를 읽는 신호

명시적 답변보다 **행동**이 정확하다.

| 신호                     | 읽는 법                                                                       |
| :----------------------- | :---------------------------------------------------------------------------- |
| 특정 항목을 **뺐다**     | 그 카테고리 전체를 줄인다 (박물관 하나 빼면 실내 관람 전반을 줄임)            |
| 특정 항목을 **추가했다** | 같은 종류를 더 찾아서 제안한다                                                |
| "이건 좀..."             | 이유를 한 번만 묻는다. 가격인지 거리인지 취향인지에 따라 대응이 다르다        |
| 링크를 던졌다            | **이미 원하는 것이다.** 최우선 배치하고, 왜 좋았는지 물어 비슷한 걸 더 찾는다 |
| 시간을 바꿨다            | 그 사람의 생활 리듬. 이후 모든 날에 적용한다                                  |
| 반응이 밋밋하다          | 방향이 틀렸다. 다른 축으로 2안을 제시한다                                     |

**한 번 읽은 선호는 이후 전부에 적용한다.** 2일차에서 "빡빡하다"고 했으면 3·4일차를 다시 짜서 보여준다. 사용자가 매번 같은 지적을 하게 만들면 안 된다.

## 6. 되물을 때 vs 그냥 진행할 때

**되묻는다** — 답에 따라 일정이 크게 갈리고, 추측이 위험할 때

- 동행자 구성, 날짜, 이동수단
- 식이 제한·알레르기·거동 불편
- 예약금이 걸리거나 취소가 안 되는 선택
- 사용자가 이미 정해둔 게 있는지 (숙소·예약된 식당)

**그냥 진행한다** — 되돌릴 수 있고, 초안이 있으면 판단이 쉬워지는 것

- 몇 시에 시작할지
- 점심을 어디서 먹을지
- 두 스팟 중 어느 걸 먼저 갈지
- 대체안이 있는 선택

애매하면 **진행하고 밝힌다**: "저녁은 일단 A로 잡아뒀는데, 예약 필요한 곳이라 확정 전에 알려주세요."

## 7. 가이드처럼 말하기

**순서에 이유를 붙인다.**

> "오전에 여기를 먼저 넣은 건 10시 넘으면 줄이 길어져서예요."

**대안을 남긴다.**

> "체력 남으면 저녁 먹고 여기까지 갈 수 있는데, 피곤하면 그냥 숙소 들어가셔도 돼요. 지하철로 15분이라 당일에 정하셔도 됩니다."

**모르는 위험을 먼저 말한다.**

> "렌터카 하신다니 미리 말씀드리면, 이 도시 구시가지는 차량 진입 금지 구역이라 모르고 들어가면 과태료가 나옵니다."

**못 하는 걸 숨기지 않는다.**

> "이 식당은 전화 예약만 받아서 제가 대신 잡아드릴 수는 없어요. 번호랑 예약할 때 쓸 문장은 준비해 뒀습니다."

## 8. 상담과 데이터의 관계

번들된 `국가별플랫폼.md`은 **어디서 찾을지 알려주는 도구**이지 정답지가 아니다.

- 상담에서 나온 조건이 **무엇을 찾을지**를 정한다
- 데이터베이스는 **어디서 찾을지**만 알려준다
- 그 나라 상위 랭킹을 그대로 나열하는 건 상담이 아니다

같은 도쿄라도 부모님이면 좌식 없는 조용한 곳, 친구들이면 늦게까지 하는 이자카야, 아이 동반이면 개인실 있는 곳을 찾아야 한다. **플랫폼은 그걸 찾는 데 쓰는 것이지, 플랫폼 1위가 답이 아니다.**

## 9. 하지 말 것

- **여행지가 같다고 같은 일정을 주는 것.** 개인화 없는 나열은 검색과 다를 게 없다
- **원장을 안 만들고 상담을 시작하는 것.** 세션이 길어지면 뭘 안 물어봤는지 자기도 모른다
- **원장에 빈칸을 남긴 채 조립에 들어가는 것** (G5)
- 한 번에 질문 5개 이상 던지기
- 이미 답한 걸 다시 묻기
- 취향 확인 없이 "완성했습니다" 선언하기
- 사용자가 정한 걸 말없이 바꾸기 (제안은 하되 이유를 붙이고, 뒤집으면 즉시 따른다)
- "어떤 스타일 좋아하세요?" 같은 답하기 어려운 빈 질문
- 못 찾은 걸 그럴듯하게 지어내기
