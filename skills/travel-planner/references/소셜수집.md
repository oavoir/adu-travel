# 소셜 수집 — 유튜브·인스타에서 진짜 정보 긁어오기

리뷰 플랫폼은 **검증**에 강하고 소셜은 **발굴**에 강하다. "지금 사람들이 실제로 가는 곳", "관광객 함정이라는 경고", "작년에 폐업했다는 제보"는 타베로그가 아니라 유튜브 챕터와 댓글에 있다.

**둘 다 쓴다.** 소셜에서 후보를 발굴하고, 플랫폼에서 영업시간·휴무·전화를 확정한다. 순서를 바꾸면 안 된다 — 소셜 정보는 부정확하고 오래됐을 수 있다.

## 0. 실측 요약 (2026-08-13 재실측)

| 소스                        | 경로                                                        | 판정                                                     |
| :-------------------------- | :---------------------------------------------------------- | :------------------------------------------------------- |
| **유튜브 검색**             | `yt-dlp "ytsearch10:<쿼리>" --flat-playlist --dump-json`    | ✅ API 키 불필요. 조회수·길이·URL                        |
| **유튜브 챕터·설명란**      | `yt-dlp --skip-download --dump-json <URL>`                  | ✅ **가장 정확.** 상호명 + 공식 사이트 링크              |
| **유튜브 자동자막**         | `yt-dlp --skip-download --write-auto-sub --sub-lang "ko.*"` | ✅ 단 고유명사 뭉개짐 · 연속 호출 시 429                 |
| **유튜브 댓글**             | `yt-dlp --skip-download --write-comments`                   | ✅ 좋아요순 정렬 가능 — **반대 신호 1순위**              |
| **인스타 개별 릴스·게시물** | `instagram.com/reel/<code>/` 을 **WebFetch로**              | ✅ 캡션 전문·계정·해시태그·게시일                        |
| **인스타 발굴**             | WebSearch `site:instagram.com <도시> 맛집`                  | ✅ 제목·스니펫에 캡션 조각                               |
| 인스타 (Bash curl)          | 같은 URL을 curl·urllib으로                                  | ❌ 600KB 껍데기 — **도구에 따라 갈린다**                 |
| 인스타 임베드·해시태그      | `/embed/captioned/` · `/explore/tags/`                      | ❌ 껍데기·JS 셸                                          |
| 💀 **레딧 전 경로**         | 아래 2절                                                    | ❌ **2026-08-13 전멸.** Bash·WebFetch·검색·브라우저 전부 |
| 💀 X 개별 트윗              | `x.com/<user>/status/<id>`                                  | ❌ WebFetch **HTTP 402 Payment Required**                |
| 💀 X 검색 페이지            | `x.com/search?q=`                                           | ❌ JS 셸                                                 |
| 💀 DuckDuckGo lite          | `lite.duckduckgo.com`                                       | ❌ 첫 요청부터 CAPTCHA                                   |

**핵심**: 검색은 **WebSearch 도구로만** 한다(덕덕고 우회는 죽었다). 인스타는 **WebFetch로만** 열린다. 레딧과 X는 **이제 경로가 없다** — 없는 걸로 계획을 세운다.

⚠️ 이 표는 스냅샷이다. 2026-08-06 실측에서 살아 있던 레딧과 X가 일주일 만에 죽었다. **소스가 안 열리면 문서가 틀린 것이지 실행이 틀린 게 아니다.** 한 번 시도해서 막히면 대체 경로로 넘어가고, 사용자에게 못 읽은 소스를 밝힌다.

## 1. 유튜브 — 가장 수확이 큰 소스

### 1-1. 영상 찾기

```bash
yt-dlp --flat-playlist --dump-json "ytsearch8:tokyo best food guide 2026" 2>/dev/null
```

JSON으로 제목·조회수·길이·URL이 나온다. 고를 때 기준:

- **조회수가 높은 것** — 검증된 정보일 확률이 높다
- **최근 것** — 2년 넘은 영상은 폐업·가격변동 위험. 제목의 연도 표기를 본다
- **길이 20분 이상** — 짧은 영상은 스팟 2~3개뿐이다. 긴 가이드 영상 하나가 짧은 것 열 개보다 낫다
- **여행지+카테고리로 쿼리를 나눈다** — `tokyo food guide`, `tokyo hidden gems`, `tokyo with parents`, `<지역명> local eats`

상담 결과를 쿼리에 넣는다. 부모님 동행이면 `tokyo travel with elderly parents`, 아이 동반이면 `tokyo with kids`가 완전히 다른 영상을 준다.

### 1-2. ★ 챕터와 설명란이 자막보다 정확하다

```bash
yt-dlp --skip-download --dump-json "<영상URL>" 2>/dev/null
```

여기서 `chapters`와 `description`을 꺼낸다. **음식 가이드 영상은 챕터 제목이 그대로 가게 이름이다.**

실측 예 (도쿄 음식 가이드 영상 하나):

```
챕터 25개 = 가게 25곳
  0:36  Shinpachi Shokudō
  1:21  SHIBUichi BAKERY
  3:24  Ichikawa Tempura
  ...
설명란: "Food & Places (in order):" 아래 상호 + 공식 사이트 URL 전부
```

**설명란에 공식 사이트 링크가 있으면 그게 최고의 팩트체크 소스다.** 영업시간을 그 사이트에서 바로 확정할 수 있다.

설명란에서 촬영 시점도 확인한다. 위 영상은 "Filmed on October 9 to 17, 2024 (prices as of date of filming)"라고 명시했다 — **가격 정보의 유효기간을 판단하는 근거**다.

### 1-3. 자막 전사 — 맥락과 평가를 얻는다

```bash
yt-dlp --skip-download --write-auto-sub --sub-lang "en.*" --sub-format vtt -o "%(id)s" "<URL>"
```

한국어 영상이면 `--sub-lang "ko.*"`. VTT는 타임코드와 중복 줄이 많아 정제해야 한다 (실측에서 246KB VTT → 26KB 텍스트).

⚠️ **자막은 연속으로 받으면 `HTTP Error 429: Too Many Requests`가 난다.** 2026-08-13 실측에서 같은 영상의 두 번째 언어를 이어서 요청하자 바로 429였다. **영상당 언어 하나만 받고**, 429가 나면 재시도하지 말고 챕터·설명란으로 넘어간다.

```python
import re
t = open(vtt, encoding='utf-8').read()
t = re.sub(r'<[^>]+>', '', t)
lines = [l.strip() for l in t.split('\n')]
lines = [l for l in lines if l and '-->' not in l
         and not l.startswith(('WEBVTT','Kind:','Language:'))]
out = []
for l in lines:
    if not out or out[-1] != l: out.append(l)      # 중복 제거가 핵심
txt = re.sub(r'\s+', ' ', ' '.join(out))
```

### ⚠️ 자동자막은 고유명사를 뭉갠다

실측 사례: "ski Tepanya"(→ Sky Teppanyaki 추정), "wagu"(→ wagyu). **자막에서 나온 가게 이름은 확정이 아니라 단서다.** 반드시 챕터·설명란과 대조하거나 플랫폼에서 검색해 실제 표기를 확정한다.

자막이 잘하는 것은 **평가와 맥락**이다. "여긴 줄이 길지만 30분이면 빠진다", "4,000엔인데 그만한 값어치는 없었다" 같은 판단이 여기 있고, 이건 플랫폼 점수에 안 나온다.

**whisper는 자동자막이 아예 없을 때만 쓴다.** 시간과 비용이 훨씬 크다.

## 2. 💀 레딧은 죽었다 — 반대 신호를 어디서 구하나

레딧의 가치는 추천이 아니라 **반대 신호**였다. "거긴 관광객만 간다", "작년에 주인 바뀌고 맛 없어졌다" 같은 정보가 거기 있었다. 그 소스가 사라졌으므로 **대체 경로를 쓴다.**

### 2-1. 사망 확인 (2026-08-13 실측 — 재시도 금지)

| 경로                                     | 결과                                               |
| :--------------------------------------- | :------------------------------------------------- |
| Bash `old.reddit.com/...`                | 200이지만 본문이 `<title>Welcome to Reddit` 게이트 |
| 풀 브라우저 헤더 세트 · 쿠키 세션 선행   | 동일 게이트                                        |
| `old.reddit.com/....json`                | 동일 게이트                                        |
| `www.reddit.com/....json`                | 403                                                |
| WebFetch                                 | 도구 레벨 차단                                     |
| WebSearch `allowed_domains:[reddit.com]` | 400 — 크롤러 차단 도메인                           |
| WebSearch `site:reddit.com` 평문 쿼리    | 레딧 결과 0건                                      |
| 브라우저 도구                            | 정책 차단                                          |
| redlib·safereddit 미러                   | 403 · 브라우저 검증 벽                             |

**여덟 경로가 전부 막혔다. 한 번도 시도하지 않는다.** 시도해봐야 호출 예산만 태우고 답이 늦어진다.

### 2-2. 대체 ① 유튜브 댓글 — 반대 신호 1순위

레딧 댓글의 기능을 가장 가깝게 대신한다. 영상은 홍보라도 **댓글은 반박이 달린다.**

```bash
yt-dlp --skip-download --write-comments \
  --extractor-args "youtube:comment_sort=top;max_comments=30,all,0,0" \
  -o "%(id)s.%(ext)s" "<영상URL>"
```

`<id>.info.json`의 `comments[]`에서 `text`와 `like_count`를 꺼내 **좋아요순으로 정렬**한다. 30건이면 충분하고, 그 이상은 시간만 든다(실측 30건 수집 확인).

읽을 때 찾는 것: 가격 지적("저 라멘값이면 …"), 대기 시간 제보, 폐업·이전 언급, 촬영 시점 이후의 변화. **칭찬 댓글은 버린다** — 이 단계의 목적은 발굴이 아니라 걸러내기다.

### 2-3. 대체 ② WebSearch 직접 조회

쿼리에 **부정 단어를 직접 넣는다.** 검색엔진은 레딧을 못 주지만 블로그·매거진·현지 매체는 준다.

```
<도시> tourist trap avoid
<도시> overrated restaurant
<도시> 관광객만 가는 곳
```

실측에서 도톤보리 뒷골목 바가지 술집·심야 호객 수법 같은 구체적 경고가 나왔다. 출처가 개인 블로그면 등급을 낮춰 잡고, 여러 소스에 같은 경고가 반복되면 신뢰한다.

### 2-4. 대체 ③ Wikivoyage

`en.wikivoyage.org/wiki/<City>`는 403이 없고(실측 200) **Stay safe · Cope 섹션에 사기·바가지 유형**이 정리돼 있다. 개별 가게 단위는 아니고 유형 단위라, 현장 판단 기준으로 쓴다.

### 2-5. 대체가 못 메우는 것을 숨기지 않는다

레딧이 있던 자리는 완전히 메워지지 않는다. **"현지 커뮤니티 반대 신호는 이번에 못 봤다"고 밝힌다.** 못 읽은 소스를 안 밝히는 것이 이 스킬에서 가장 큰 사고다.

## 3. 💀 X (트위터) — 경로 없음

개별 트윗 URL이 2026-08-06까지는 읽혔지만 **2026-08-13 실측에서 WebFetch가 `HTTP 402 Payment Required`를 반환한다.** 검색 페이지는 종전대로 JS 셸이다.

WebSearch로 트윗 **URL을 찾는 것까지는 되지만 열리지 않는다.** 검색 결과 제목에 실린 문장 조각까지가 얻을 수 있는 전부이고, 그건 근거로 쓰기에 부족하다.

**X는 조사 계획에서 뺀다.** 최신성이 필요하면 유튜브 최근 영상(업로드 3개월 이내)과 인스타 게시일로 대신한다.

## 4. 인스타그램 — 링크를 안 줘도 찾아낼 수 있다

**한국 여행 콘텐츠가 가장 두껍게 쌓인 곳이다.** 한국인 여행 계정이 도쿄·오사카 맛집 리스트를 캡션에 통째로 적어두는 문화가 있어서, 한국어 검색으로 접근하면 수확이 크다.

### 4-1. 발견 — 검색으로 게시물을 찾는다

**WebSearch 도구로** `site:instagram.com <도시> 맛집` 을 친다. 덕덕고 우회(`lite.` · `html.`)는 CAPTCHA로 죽었으니 쓰지 않는다.

**제목과 스니펫에 캡션 조각이 실린다.** 실측에서 결과 하나에 가게 이름이 그대로 나열돼 있었다.

```
"할명수 도쿄편 맛집 추천 9 — 고다이메 하나야마우동 긴자점 / 하야시야신베에 /
 호카이반야 야키니쿠 / 팡메종 긴자점 / 긴자 돈카츠 사이토 / 쓰키시마 몬자야키 ..."
```

**게시물을 열지 않고도 후보 목록이 나온다.** 좋아요·댓글 수와 게시일도 스니펫에 실려서 신선도 판단까지 된다.

계정 자체도 찾아진다. 특정 도시 전문 계정(팔로워 수만 명대)을 발견하면 그 계정의 게시물을 더 파고들 수 있다.

### 4-2. 개별 게시물 — ⚠️ 반드시 WebFetch로

```
✅ WebFetch("https://www.instagram.com/reel/<code>/")   → 캡션 전문 나옴
❌ Bash에서 curl·urllib으로 같은 URL                     → 껍데기
```

**같은 URL인데 도구에 따라 결과가 갈린다.** curl은 200에 600KB를 주지만 `og:description`이 0건이라 **크기만 보고 성공으로 판정하면 안 된다**(2026-08-13 실측 — 예전의 "9자 껍데기"에서 응답만 커졌고 알맹이는 그대로 없다). 판정은 캡션 텍스트가 실제로 잡히는지로 한다.

실측에서 나온 필드: 계정명 · **캡션 전문** · 해시태그 · 게시일. 2026-08-13 재확인에서도 캡션·핸들·게시일이 그대로 나왔다.

### 4-3. ⚠️ 한글 음차를 확정 표기로 쓰지 않는다

인스타 캡션은 한국인이 쓴 것이라 가게 이름이 **한글 음차**로 적혀 있다. "츠지한"은 실제로 `つじ半`이고, 이걸로 타베로그를 검색하면 못 찾는다.

유튜브 자막이 고유명사를 뭉개는 것과 같은 문제다. **음차는 단서일 뿐이고, 플랫폼에서 실제 표기를 확정해야 한다.** 위치태그와 해시태그가 힌트가 된다.

### 4-4. 여전히 안 되는 것

- **해시태그·탐색 페이지는 JS 셸**이다. 반복 fetch해봐야 안 나온다
- **슬라이드 이미지 안의 텍스트**는 캡션에 없다. 캐러셀은 `references/인스타추출.md`의 브라우저 파이프라인으로 슬라이드를 넘겨야 한다
- 임베드 엔드포인트(`/embed/captioned/`)는 예전 우회로였으나 지금은 막혔다

사용자가 링크를 직접 던진 경우는 **이미 사용자가 원하는 것**이므로 최우선으로 다루고, `인스타추출.md` 파이프라인을 끝까지 돌린다.

## 5. 수집한 것을 어떻게 쓰는가

### 소셜 → 플랫폼 → 일정 순서를 지킨다

```
소셜에서 발굴          "이 유튜버가 12곳 추천, 댓글 상위에서 그중 2곳은 가격이 올랐다고 함"
   ↓
플랫폼에서 확정        타베로그에서 실제 표기·점수·영업시간·정기휴무·전화 확인
   ↓
상담 조건으로 필터     어르신 동행이니 좌식·대기 긴 곳 제외
   ↓
동선으로 배치          그날 클러스터에 맞는 것만
```

**소셜 정보를 그대로 일정에 넣지 않는다.** 이름이 뭉개졌을 수 있고, 폐업했을 수 있고, 영업시간이 바뀌었을 수 있다.

### 교차 신호를 우대한다

**여러 소스에 동시에 나온 곳**이 가장 안전하다. 유튜브 챕터에도 있고 인스타 캡션에도 있고 플랫폼 점수도 높으면 거의 확실하다. 반대로 한 소스에만 나오고 플랫폼에서 안 잡히면 의심한다.

레딧이 빠지면서 **교차 신호의 축이 하나 줄었다.** 그래서 남은 축(유튜브 챕터·유튜브 댓글·인스타 캡션·플랫폼 점수)에서 최소 둘이 겹치는지를 종전보다 엄격하게 본다.

### 출처를 남긴다

조사 결과 테이블에 **어느 영상·어느 게시물에서 나왔는지** 적는다. 사용자가 "이건 왜 넣었어?"라고 물으면 "조회수 52만 도쿄 음식 가이드 영상 챕터에 있었고 타베로그 3.6으로 확인했다"고 답할 수 있어야 한다.

## 6. 하지 말 것

- **자막에서 뽑은 가게 이름을 그대로 확정하는 것** — 고유명사가 뭉개진다
- **인스타 캡션의 한글 음차를 실제 상호로 쓰는 것** — "츠지한"으로는 타베로그에서 못 찾는다
- **인스타를 Bash curl로 여는 것** — 200에 600KB가 와도 캡션은 없다. 인스타는 WebFetch만
- 소셜 정보를 플랫폼 검증 없이 일정에 넣는 것
- 조회수만 보고 고르는 것 — 촬영 시점을 반드시 확인한다
- **레딧·X·덕덕고를 시도하는 것** — 2026-08-13 기준 전 경로 사망이다. 호출 예산만 태운다
- X 검색 페이지나 인스타 해시태그 페이지를 반복 fetch하는 것 (JS 셸이라 영원히 안 나온다)
- **레딧이 죽었다는 걸 사용자에게 안 밝히는 것** — 반대 신호를 못 본 채로 일정을 내밀면 그게 사고다
- **로그인이 필요한 곳에 로그인을 시도하는 것.** 사용자 계정으로 열 때는 읽기만 한다
